## Scheduling — a structural fault in this agent's own priority queue

The 13 Aug run set as its top-priority next action: *"Log the 14 August PTTEP open
against the theoretical ex-price."* **That task was impossible when it was
written.** This run begins at 02:30 ICT on 14 August; the SET opens at 10:00 ICT,
**7.5 hours later**. A 02:30 nightly agent can *never* observe a same-day open.

This is not a data gap — it is a category error about what a nightly agent can
observe. It would have recurred silently every time an event was queued for
"tomorrow". Two consequences adopted:

1. Same-day-open observations must be queued for the run **after** the session,
   i.e. the 15 August run for the 14 August open.
2. `set_quote_parser.session_date_for()` encodes the underlying rule: a `Closed`
   stamp before 10:00 ICT describes the **previous** session, never the current
   calendar day. Verified — the 02:35 stamps resolved to 2026-08-13, not 08-14.
